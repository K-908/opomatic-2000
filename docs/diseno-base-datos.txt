DISEÑO DE BASE DE DATOS DE OPOMATIC-2000
MYSQL; ESQUEMA INICIAL EN ../database/schema.sql

1. ESTADO

Se parte de una base vacía. El archivo SQL crea nueve tablas en MySQL 8.0.16+
con InnoDB y utf8mb4. Fue importado y probado en MySQL 8.0.46. Este documento
describe el objetivo del backend PHP, que aún no está implementado. No se
importan filas de SQL Server ni de SQLite.

2. CATÁLOGO Y RELACIONES

- Users: `Username` (clave), `PasswordHash`. Solo las cuentas cerradas del
  producto; no hay registro público. El hash se crea con `password_hash()`.
- LoginAccesses: acceso correcto, usuario, fecha UTC e IP observada. El diseño
  conserva el nombre de usuario aunque la cuenta se modifique más adelante.
- Topics: nombre único, estado activo y fechas de creación/actualización.
- Questions: tema, enunciado, estado activo y fechas. Cada pregunta pertenece
  a un tema; la desactivación de tema excluye sus preguntas de nuevos tests.
- QuestionOptions: cuatro opciones por pregunta, posición 1..4 y marca de
  corrección. La regla de exactamente cuatro y una correcta se valida en PHP
  dentro de una transacción; el esquema impide posiciones duplicadas.
- TestAttempts: entrega con `SubmissionId` único, usuario, fecha, contadores,
  nota y versión de puntuación. El `Score` es BIGINT en millonésimas de punto.
- TestAttemptTopics: temas elegidos y nombre capturado al entregar.
- TestAttemptQuestions: preguntas, orden, texto, tema y resultado capturados.
- TestAttemptOptions: opciones, orden, texto, selección y corrección capturados.

Las filas de snapshot mantienen además referencias a los originales; no se
eliminan físicamente temas ni preguntas que tengan histórico. Las relaciones
con el intento usan cascada para poder limpiar un intento completo en pruebas.

3. RESTRICCIONES

Claves foráneas, unicidad e índices están en `schema.sql`. Los CHECK validan
posición, contadores, rango de nota y resultado. La regla de una única opción
correcta por pregunta, separación de usuarios y consistencia del token
requieren validación del backend. La importación JSON y la entrega del test
deben confirmar o revertir todas sus filas como una sola operación.

Los nombres de tema se normalizan antes de guardar. La comparación sin
mayúsculas depende de la colación `utf8mb4_unicode_ci`; hay que verificar el
comportamiento de acentos y espacios con los casos de aceptación. Los nombres
de tablas se usan tal como aparecen en SQL; en servidores Linux debe respetarse
su capitalización al escribir consultas.

4. CONFIGURACIÓN Y COPIAS

PDO recibe host, puerto, base, usuario y contraseña desde una configuración no
versionada. No se expondrán errores de conexión ni secretos al navegador.
phpMyAdmin permite importar el esquema y exportar copias SQL. Las copias deben
guardarse fuera del directorio público y probarse mediante restauración en una
base separada.

5. EVOLUCIÓN

No se reimportará `schema.sql` sobre una base con datos. Las modificaciones
posteriores se harán con scripts incrementales versionados y comprobados en una
base de prueba antes de aplicarlos al hosting.
